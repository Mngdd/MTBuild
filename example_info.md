# Генератор неструктурированных 2D-сеток — техническая справка для реализации (Go)

Источник: диплом "Разработка программных инструментов автоматизированного построителя
неструктурированных сеток" (МГТУ им. Баумана). Метод объединяет: QuadTree, level-set,
SPH-релаксацию частиц, триангуляцию Делоне.

## 0. Общий пайплайн (порядок вызовов)

1. Построить входную геометрию — замкнутую ломаную (polyline) границы объекта.
2. Построить фоновую адаптивную decartову сетку (QuadTree), сгущённую у границы.
3. Посчитать на ней три скалярных поля: φ (signed distance), ψ (distance to singularities),
   κ (curvature, диффундированная внутрь).
4. Из φ, ψ, κ получить целевую функцию размера элемента h_t(x,y) и целевую плотность ρ_t(x,y).
5. Инициализировать частицы (внутренние + граничные) с целевой плотностью.
6. Запустить SPH-релаксацию частиц (итеративный цикл сил давления + вязкости) до сходимости.
7. По финальным позициям частиц построить триангуляцию Делоне → это и есть выходная сетка.
8. Посчитать метрики качества сетки (G_avg, θ_min и т.д.).

Вход: контур геометрии (ломаная) + 4 числовых параметра (h_max, h_max_s, h_min_s, kappa_a).
Выход: 2D-триангуляция (список вершин + список треугольников), не 3D-модель.

## 1. QuadTree — фоновая сетка переменного разрешения

Зачем: избежать равномерной сетки (дорого) и полностью неструктурированной (сложна
навигация). Иерархическая структура: каждая ячейка либо лист, либо имеет ровно 4 потомка.

### Структура узла
```go
type QuadNode struct {
    Parent       *QuadNode
    Children     [4]*QuadNode // nil если лист
    GhostChildren [4]*QuadNode // виртуальные соседи большего размера (для согласования данных на границе разных разрешений)
    Depth        int
    I, J         int     // индексы ячейки на своём уровне глубины
    // Хранимые поля:
    Phi, Psi, Kappa float64
    Ht, RhoT        float64
}
```

### Индексация детей (при разбиении родителя на 4)
```
i_child = 2*i_parent + delta_i(pos)
j_child = 2*j_parent + delta_j(pos)
```
| pos | квадрант | delta_i | delta_j |
|-----|----------|---------|---------|
| 0   | SW       | 0       | 0       |
| 1   | SE       | 1       | 0       |
| 2   | NE       | 1       | 1       |
| 3   | NW       | 0       | 1       |

Соседи по индексам на одном уровне: (i±1, j), (i, j±1).

### Поиск расстояния до границы
Используется R-tree по всем отрезкам входной ломаной (bounding box на каждый сегмент).
Позволяет находить ближайший отрезок за ~O(log N). Строится один раз (геометрия статична).
Для Go: можно взять готовую R-tree библиотеку (`github.com/dhconnelly/rtreego` или аналог)
или для минимального примера — просто перебор отрезков (если их немного).

### Правило адаптивного дробления
Требуемый размер ячейки в зависимости от расстояния d до ближайшего ребра e:
```
h_req(d, e) = h_max_e                      если d >= d_coarse_e
            = h_max_e * (d / d_coarse_e)   если d <  d_coarse_e
```
Ячейка дробится (на 4), если:
- h_cell > h_req, И
- (ячейка пересекается с границей ИЛИ находится в пределах d_coarse_e от неё)

### Балансировка 2:1
Соседние ячейки не должны отличаться по размеру более чем в 2 раза:
```
max(h_cell, h_neighbor) / min(h_cell, h_neighbor) <= 2
```
Если нарушено — крупная ячейка принудительно дробится. Повторять до устранения дисбалансов.

## 2. Level-set поля: φ, ψ, κ

### 2.1 Signed distance function φ
Граница Γ = {(x,y) | φ(x,y) = 0}. φ > 0 внутри области, φ < 0 снаружи, |φ| = евклидово
расстояние до Γ.

Нормаль и кривизна:
```
N = grad(phi) / |grad(phi)|
kappa = div( grad(phi) / |grad(phi)| )
```
(численно — конечные разности на сетке QuadTree)

### 2.2 Реинициализация φ (распространение вглубь области)
φ честно вычисляется только в узкой полосе у границы (через R-tree). Чтобы получить φ
во всём домене с условием |grad(phi)| = 1, решают уравнение Гамильтона-Якоби псевдо-итерациями:
```
d(phi)/d(tau) + sign(phi) * (|grad(phi)| - 1) = 0
```
tau — псевдо-шаг по времени (не физическое время), tau = 0.5 * dx. Решается до сходимости
(итеративная схема upwind, детали в Приложении А диплома).

### 2.3 Поле расстояния до сингулярностей ψ
Отдельная функция — расстояние до острых углов/кромок геометрии. Решается похожей системой:
```
psi_tau + sign(psi)*(|grad(psi)| - 1) = 0      (аналог реинициализации)
psi_tau ± N . grad(psi) = 0                    (распространение из одной фазы в другую)
```
Расчётная область — полоса вокруг контура (~2 ячейки с каждой стороны).

### 2.4 Диффузия кривизны κ вглубь области
κ известна честно только НА границе. Чтобы получить κ в окрестности (не только на линии),
решают уравнение диффузии вдоль нормали:
```
d(kappa)/d(tau) = div( (N . grad(kappa)) * N )
```
Начальные условия: в cut-ячейках (пересекающих границу) значение уже посчитано, иначе 0.
Граничные условия: cut- и border-ячейки — значения фиксированы. Псевдошаг tau = 0.5*dx^2.

### 2.5 Коррекция κ у сингулярностей (важно!)
Реальная кривизна κ уходит в бесконечность у острых углов — нужен "предохранитель".
Пользователь задаёт число kappa_a (искусственная максимальная кривизна). Формула:
```
kappa_final = max( kappa, (1 - psi/psi_max) * kappa_a )
```
- Далеко от сингулярности (psi большое): второе слагаемое ~0 → используется настоящая kappa.
- У сингулярности (psi ~0): второе слагаемое ~kappa_a → подменяет "взрывающуюся" kappa.
- Плавный линейный переход между этими случаями.

## 3. Целевой размер элемента h_t и плотность ρ_t

h_t — это НЕ размер ячейки QuadTree, а желаемый размер СТОРОНЫ БУДУЩЕГО ТРЕУГОЛЬНИКА
финальной сетки в данной точке пространства. Обратно пропорционален кривизне
(чем сильнее изогнута/острая геометрия — тем меньше h_t).

```
h_t = f(phi, psi, kappa)
rho_t = g(phi, psi, kappa)
```
(f и g — эмпирические формулы, комбинирующие три поля; в дипломе — раздел 3.2.4,
конкретный явный вид формулы даётся через целевую плотность масс, см. форм. (11)-(14)
в оригинале, для MVP можно взять упрощённую монотонную зависимость от phi/psi/kappa).

Пользовательские параметры (4 шт.):
- `kappa_a`   — искусственная макс. кривизна у сингулярностей
- `h_max`     — максимальный размер элемента вдали
- `h_max_s`   — максимальный размер элемента у границы (surface)
- `h_min_s`   — минимальный размер элемента у границы (surface)

Хранение: h_t и rho_t считаются кусочно-постоянными в ячейках QuadTree, а для произвольной
точки (например, положения SPH-частицы) получаются билинейной интерполяцией:
```
h_i ≈ theta * h_t(r_i)   // theta — масштабирующий коэффициент (регулируется по ходу расчёта)
```

## 4. SPH-релаксация частиц

### 4.1 Модель
Лагранжева сжимаемая вязкая "жидкость" из частиц — не настоящая физика, а инструмент
для равномерной/адаптивной расстановки точек:
```
d(rho)/dt = -rho * div(v)
d(v)/dt   = -F_p + F_v
```
Искусственное уравнение состояния (давление растёт при отклонении от целевой плотности):
```
p = p0 * (rho / rho_t)^2      // p0 обычно = 1 (эмпирически хорошо работает)
```
rho_t частицы получается билинейной интерполяцией из целевого поля плотности (см. раздел 3).

### 4.2 Ядро сглаживания W (кубический сплайн)
```
s = r_ij / h
W(r_ij, h) = alpha * (s^3 - 6s + 6)      если 0 <= s < 1
           = alpha * (2 - s)^3           если 1 <= s < 2
           = 0                           если s >= 2
alpha = 1 / (3*pi*h^2)     // 2D нормировка
```
Радиус обрезания взаимодействия r_c = 2h (за пределами — соседей не учитываем).

### 4.3 Сила давления (дискретная, между частицами i,j)
```
F_p,i = sum_j m_j * (p0/rho_t_i^2 + p0/rho_t_j^2) * dW/dr_ij * e_ij
```
где e_ij = (r_i - r_j)/|r_i - r_j| — единичный вектор от j к i.
Реальная плотность НЕ вычисляется явно — используется целевая (rho_t), что упрощает расчёт.

### 4.4 Ренормализация у границы (важно для устойчивости)
Коэффициент γ_i (аналог веса Шепарда), нужен чтобы частицы у самой границы не "проваливались"
из-за нехватки соседей с одной стороны:
```
gamma_i = sum_j W(r_ij, h_i) * V_t_j      // V_t_j = h_t_j^d  (d = размерность, здесь 2)
```
Финальная сила давления с учётом границы (i — внутренняя частица, b — граничная частица):
```
F_p,i = (1/gamma_i) * sum_j [...] + (1/gamma_i) * sum_b (p0/rho_t_i^2 + p0/rho_t_b^2) * W(r_ib,h_ib) * n_b * A_t_b
```
Физический смысл: доп. слагаемое — отталкивающая сила от границы, не даёт частицам
"протекать" через контур в отрицательную фазу. Благодаря этому НЕ нужна аккуратная
предварительная расстановка граничных частиц и последовательная иерархия эволюции.

### 4.5 Сила вязкости
```
F_v,i = sum_j [2*eta_i*eta_j/(eta_i+eta_j)] * m_j * (1/rho_i^2 + 1/rho_j^2) * dW/dr_ij * v_ij/r_ij
eta = rho * nu                    // динамическая вязкость
nu ~ 0.1 * r_c * |v|              // кинематическая вязкость (эмпирика, Re ~ O(10))
v_ij = v_i - v_j
```
После каждого обновления позиций — скорости обнуляются (v=0), чтобы гасить колебания
и быстрее выйти на стационарное состояние (актуально после "фазы разгона").

### 4.6 Главный цикл (Алгоритм 3 из диплома)
```
1. Инициализировать SPH: параметры, N_p (внутр.) и N_p_s (граничных) частиц.
2. Вычислить h_t, rho_t (см. раздел 3) заранее — до цикла.
3. while не сошлось:
   a. Пересчитать соседей (spatial hashing / Verlet list) — НЕ полный перебор O(N^2)!
   b. Обнулить силы давления.
   c. По фазе расчёта — обнулить скорости (см. 4.7 "двухфазная модель").
   d. Посчитать gamma_i (4.4).
   e. Посчитать F_p (4.3–4.4).
   f. Убрать накопленную силу в нормальном направлении для поверхностных частиц
      (чтобы граничные частицы двигались только ВДОЛЬ границы, не отрывались от неё).
   g. Задать шаг по времени dt (условие устойчивости CFL-типа).
   h. Обновить промежуточную скорость (полу-шаг, leap-frog схема).
   i. Посчитать F_v (4.5).
   j. Обновить финальную скорость и позицию (интегрирование по времени).
   k. Спроецировать surface-частицы обратно на геометрическую поверхность (не дать им
      "уплыть" с контура — коррекция позиции).
4. Вывести финальные позиции частиц.
```

### 4.7 Двухфазная модель релаксации
- Фаза 1 (разгон): импульс накапливается свободно, для быстрого выхода на целевое
  распределение размеров/плотности.
- Фаза 2 (стабилизация): периодическое обнуление скоростей + доп. демпфирование —
  подавление высокочастотного "звона"/шума и финальная полировка качества.

### 4.8 Быстрый поиск соседей
Обязательно нужна пространственная структура (не перебор всех пар частиц):
- динамический связный список ячеек (spatial hash grid) + список Верле (Verlet list) —
  список соседей кэшируется на несколько шагов и обновляется не каждую итерацию.
- Для Go MVP: можно сделать простую uniform grid hash map[CellKey][]ParticleID с ячейкой
  размера ~r_c.

## 5. Триангуляция Делоне (финальный шаг)

Вход: финальные позиции всех частиц (внутренних + граничных) после сходимости SPH.
Выход: набор треугольников (индексы вершин).

Для Go: НЕ писать Делоне с нуля для MVP — использовать готовую библиотеку, например:
- `github.com/fogleman/delaunay`
- `github.com/pion/go-delaunay` (проверить актуальность/наличие)
- альтернативно — обёртка над Qhull/Triangle через cgo.

В дипломе используется распараллеленная реализация (не обязательно для MVP).

## 6. Метрики качества сетки (для валидации результата)

Для треугольника: `G = 2*sqrt(3)*S / (p*h)`, где S — площадь, p — полупериметр,
h — длина наибольшей стороны. Идеальный (равносторонний) треугольник: G ≈ 1, все углы 60°.

Считать по всей сетке:
- G_min, G_avg — минимальное и среднее качество
- theta_min, theta_avg — минимальный угол по треугольникам (мин. и среднее)
- % треугольников с минимальным углом < 30° (индикатор "плохих" элементов)
- гистограмма углов (для визуальной проверки регулярности)

Референсные цифры из диплома (для сверки правильности реализации):
- Zalesak disk: G_avg≈0.91, G_min≈0.54, углы 27°–110°, лишь 3 треугольника с углом <30°.
- Профиль крыла (внешняя область): G_avg≈0.92.
- Профиль крыла (внутренняя область, недосходившийся случай): G_avg≈0.87 — хуже из-за
  раннего останова по лимиту итераций, не по фактической сходимости.

## 7. Рекомендации по MVP на Go (минимальный рабочий пример)

Для первой версии не обязательно реализовывать всё "как в дипломе" — можно сильно упростить:

1. **Геометрия**: жёстко закодировать простой контур (например, эллипс или Zalesak disk
   как набор точек) вместо парсинга произвольных файлов.
2. **QuadTree**: можно урезать до фиксированной глубины дробления по правилу
   "дели, если рядом граница", без полной 2:1-балансировки на первом шаге.
3. **φ**: для простых аналитических форм (круг, эллипс) φ можно посчитать напрямую
   аналитической формулой, а не через R-tree + реинициализацию — сильно упрощает MVP.
4. **ψ, κ**: для первого прохода можно вообще пропустить (считать κ=0 везде, h_t зависящим
   только от φ) — получится равномерное сгущение у границы без учёта остроты углов.
   Это уже даст рабочую, пусть менее умную, генерацию сетки.
5. **SPH**: обязательная часть — без неё нет адаптивной расстановки точек. Начать с
   простой uniform grid для соседей, кубическое ядро, только силу давления (без вязкости)
   — и посмотреть, сходится ли расстановка вообще.
6. **Делоне**: сразу взять готовую библиотеку, не писать самому.
7. **Проверка**: посчитать G_avg/theta_avg и сравнить с референсом (Zalesak disk) —
   если в похожем диапазоне (G_avg 0.85-0.95) — метод реализован в целом верно.

## 8. Порядок реализации (предлагаемый, по шагам разработки)

1. Структуры данных: Point, Particle, QuadNode, Mesh (triangles+vertices).
2. Геометрия: полилиния границы + функция "расстояние от точки до полилинии" (брутфорс ок для MVP).
3. Аналитическое или численное φ на простой равномерной/quadtree сетке.
4. h_t как простая функция от φ (например: h_t = h_min_s + (h_max-h_min_s)*clamp(|phi|/D, 0, 1)).
5. Инициализация частиц: случайная/регулярная расстановка с плотностью ~1/h_t^2.
6. SPH цикл: соседи → сила давления → интегрирование → повтор N итераций или до сходимости.
7. Экспорт частиц → вызов Delaunay-библиотеки → получить треугольники.
8. Посчитать метрики качества, отрисовать SVG/PNG для визуальной проверки.
