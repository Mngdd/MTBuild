# MTBuild

MVP генератора неструктурированных сеток 

Алгоритм краткой справкой — [`example_info.md`](example_info.md).
GUI подробно — [`ui/README.md`](ui/README.md).

---

## Запуск

Нужен Go 1.24+. Зависимости подтянутся сами (`go.mod`).

GUI:

```bash
go run ./ui
```

Контур (пресет `ellipse`/`circle`/`zalesak`/`wing` или свой `.dxf`), алгоритм и его
параметры выбираются в окне — верхнее меню, список слева, слайдеры в
детальной панели. Подробнее про сам интерфейс — [`ui/README.md`](ui/README.md).

CLI (headless — для скриптов/экспорта/быстрой проверки параметров без окна):

```bash
go run ./cmd/mtbuild-cli -geom zalesak -algo sph-quadtree -param iters=400 -svg mesh.svg -out mesh.msh
```

Тесты:

```bash
go test ./...
```

### Параметры алгоритма `sph-quadtree`

Задаются в **долях габаритного прямоугольника** геометрии (не в мировых единицах),
поэтому одинаково работают для любой фигуры. Кривизна — в единицах `1/доля`.
В GUI это слайдеры в панели алгоритма, диапазоны те же:

| ключ | смысл | диапазон | дефолт |
|---|---|---|---|
| `h_max` | размер элемента вдали от границы | 0.01–0.5 | 0.09 |
| `h_max_s` | размер элемента на гладком участке границы | 0.005–0.4 | 0.06 |
| `h_min_s` | размер элемента на остром участке границы | 0.003–0.3 | 0.02 |
| `grade` | дистанция, на которой размер растёт от границы до `h_max` | 0.02–1.0 | 0.25 |
| `kappa_a` | кривизна, при которой размер достигает `h_min_s`; `0` отключает адаптацию по кривизне | 0–500 | 15 |
| `sharp_deg` | угол поворота контура, считающийся сингулярностью (острым углом) | 5–90 | 25 |
| `iters` | максимум итераций SPH | 10–3000 | 250 |
| `smooth_passes` | проходов сглаживания Лапласа + перетриангуляции после SPH (не из диплома, но качество SPH выходит на плато задолго до `iters` — это даёт реальный прирост) | 0–10 | 3 |
| `weld_tol` | частицы ближе `weld_tol·h_min_s` склеиваются перед Делоне (склейка всегда включена, настраивается только расстояние) | 0.0001–0.5 | 0.2 |

Алгоритм `grid` (тривиальный baseline): один параметр `h` — шаг решётки в мировых единицах.

### Параметры алгоритма `charge-voronoi`

Второй алгоритм, физически другой принцип: центры ячеек — одноимённые заряженные частицы,
отталкивание `F = k/rⁿ`, с диссипацией — оседают в примерно равномерную упаковку. Итоговые
ячейки — не Делоне-треугольники, а **многоугольники Вороного** вокруг осевших частиц
(`Mesh.Cells`, не `Mesh.Triangles`). Подробнее — заголовок пакета `internal/mesher/charge`.
Параметры тоже в долях габарита:

| ключ | смысл | диапазон | дефолт |
|---|---|---|---|
| `h` | целевой шаг между центрами ячеек | 0.02–0.5 | 0.09 |
| `n` | показатель степени в законе силы `F = k/rⁿ` | 1–4 | 2 |
| `k` | коэффициент силы | 0–1 | 1 |
| `damping` | затухание скорости за шаг (диссипация) | 0.5–0.99 | 0.85 |
| `clamp` | флаг: ограничивать смещение частицы за шаг (`-param clamp=0` — выкл) | 0/1 | 1 |
| `max_step` | предел смещения за шаг, в долях `h` (в GUI виден только при `clamp`) | 0.05–1 | 0.3 |
| `separate` | флаг: разводить совпавшие частицы (вдоль разности скоростей, при нулевой — в случайную сторону); при 0 слипаются. Перед Делоне совпавшие склеиваются всегда | 0/1 | 1 |
| `weld_tol` | вершины ячеек ближе `weld_tol·h` склеиваются в одну (всегда; убирает ложные рёбра ~0 длины от почти «круговых» четвёрок частиц — максимум шестиугольников около 0.02) | 0.0001–0.1 | 0.02 |
| `iters` | итераций релаксации | 10–2000 | 300 |

Метрики — не `QualityMetrics` (та для треугольников), а `mesh.PolyQualityMetrics`:
среднее/мин/макс число сторон + гистограмма, изопериметрический коэффициент
`4π·Area/Perimeter²` (1.0 у круга, ~0.91 у правильного шестиугольника — аналог `G` для
многоугольников) и коэффициент вариации площади ячеек. На круге алгоритм выходит на
`avg_sides ≈ 6.2`, `iso_avg ≈ 0.85` — близко к идеальной сотовой укладке.

Сетка связная: вершина ячейки — циркумцентр треугольника Делоне, и её id = номер треугольника,
так что соседние ячейки ссылаются на одну вершину, а не на свои копии. Ячейки строятся только для
**внутренних** частиц — граничные заряды лишь стенки для релаксации. До контура ячейки дотягивают
**отражения**, как в PolyMesher (Talischi и др., 2012): частица ближе `1.5h` к краю отражается
через ближайшую точку контура (`p' = 2q − p`), Делоне строится по «внутренние + отражения», и
граница между частицей и её отражением сама ложится на контур. Вершины между частицей и
отражением (и любые вне фигуры) прижимаются на контур. Отражение, попавшее внутрь фигуры (узкие
места, вогнутые углы), выкидывается. Отражение одно, поэтому в углах ячейки срезаны (см. TODO).

data/                     картинки (иконка, логотип) + data.go, вшивающий логотип в бинарник (go:embed).

                          Оба подключают алгоритмы анонимным импортом (_ ".../sphquad") ради
                          init()-регистрации — сами ничего не знают про конкретные алгоритмы.

  mesher/                  КОНТРАКТ «чёрной коробки»
    mesher.go               Mesher (Name/Params/Generate), ParamSpec (Kind/DependsOn), Params.Get/Bool, Frame, Sink, NopSink
    particles.go            ParticleMetrics (сдвиг за шаг, разброс до ближайшего соседа) + NeighborSpread

                            отсортированные по углу. Выход — Mesh.Cells (многоугольники), не Triangles.
    sphquad/                МЕТОД ИЗ ДИПЛОМА
      sphquad.go              оркестрация всего пайплайна (см. ниже)

      field/
        field.go              φ — signed distance брутфорсом по сегментам
        analyze.go            ψ (расстояние до острых углов) + κ (дискретная кривизна границы) + коррекция κ у сингулярностей
      quadtree/quadtree.go    адаптивная фоновая сетка: дробление у границы, 2:1-балансировка, LeafAt

        kernel.go             кубический сплайн-ядро W(r,h) и dW/dr (форма из диплома)

        sph.go                цикл релаксации: давление с ренормализацией Шепарда γ_i + отталкивание

Зависимости между пакетами направлены строго вниз: `ui`/`cmd/mtbuild-cli` → `mesher` + `viz`;

Алгоритм никогда не знает про `ui`, `cmd`, `viz` и другие алгоритмы.

## Что на входе и что на выходе

### Вход

1. **Геометрия** — замкнутый контур (внешняя граница + опционально дырки).
   Источник:
   - `.dxf` файл. Поддерживаются сущности `LWPOLYLINE`, `SPLINE` (разворачивается в
     ломаную алгоритмом Де Бура), `LINE` (отрезки сшиваются в петли по общим концам).
     Если замкнутых контуров несколько — самый большой по площади становится внешним,
     остальные дырками.
   - либо имя встроенного пресета.

   Файл превращается в `geometry.Geometry{Outer geometry.Polyline, Holes []geometry.Polyline}` —
   это всё, что видит алгоритм. Парсинг файла — забота приложения, не алгоритма.

2. **Параметры** — `map[string]float64`. Какие ключи бывают — алгоритм декларирует сам
   через `Params() []ParamSpec` (ключ, лейбл, min/max/дефолт/шаг). Не заданные ключи
   берутся из дефолтов, значения зажимаются в диапазон. Флаги — `Kind: KindBool`
   (значение 0/1, читается `Params.Bool`, в GUI — чекбокс, в CLI `-param key=1`).
   `DependsOn: "<ключ флага>"` — GUI показывает параметр только при включённом флаге.

3. **`context.Context`** — для отмены расчёта.

4. **`Sink`** — куда алгоритм по ходу работы сливает прогресс (`Progress(stage, frac)`)
   и промежуточные снимки (`Snapshot(Frame)` — позиции частиц, стадия, номер итерации,
   а на финале и готовая сетка). Кадры итерационных стадий (раз в 10 итераций) несут ещё
   `Frame.Particle` — дешёвые метрики частиц — и `Frame.BuildMesh`: построить по текущим
   частицам сетку тем же путём, что и итоговую (дорого, поэтому зовёт её только тот, кому
   нужно, и только внутри `Snapshot`). GUI по ним рисует историю метрик по итерациям
   (`ui/metrics.go`); CLI печатает прогресс в stderr, тесты — `NopSink{}`.

### Выход `Generate(...)`

- **`mesh.Mesh`** — `Vertices []geometry.Point` + `Triangles [][3]int` (индексы вершин).
  Плоская 2D-триангуляция, не 3D-модель.
- **`mesh.QualityMetrics`** — число треугольников, `GAvg`/`GMin`, `ThetaMinDeg`/`ThetaAvgDeg`,
  доля треугольников с углом <30°, гистограмма всех углов по 15°-корзинам.
- **`error`** — при вырожденной геометрии, отмене по контексту, сбое триангуляции.

GUI дополнительно рисует сетку векторно, с зумом и сдвигом (`ui/view.go`).

### Пайплайн `sph-quadtree` внутри

```
Geometry
  └─ нормализация в единичный габарит (координаты → доли bbox, центр в 0)
       └─ поля: φ = signed distance; ψ = расстояние до острых углов;
          κ = дискретная кривизна ближайшей точки границы;
          κ_final = max(κ, (1 − ψ/ψ_max)·kappa_a)
            └─ h_t(x):  h_surf = h_max_s − (h_max_s − h_min_s)·clamp(κ_final/kappa_a)
                        h_t    = h_surf + (h_max − h_surf)·clamp(|φ|/grade)
                 └─ QuadTree: адаптивное дробление у границы + 2:1-балансировка (несёт φ и h_t на листьях)
                      └─ посев частиц:
                           • граничные — вдоль контура с шагом h_t
                           • внутренние — jittered-решётка, прорежена под плотность 1/h_t²
                           └─ SPH-релаксация (двухфазная: разгон с импульсом → полировка с обнулением скорости):
                                соседи (uniform hash) →
                                  γ_i (вес Шепарда, форма 35) →
                                  давление −(1/γ_i)·p0·(h_i⁴+h_j⁴)·∇W + отталкивание от границы (форма 36) →
                                  вязкость (форма 26) →
                                  leap-frog с шагом dt по CFL → сдвиг → сбежавших вернуть внутрь
                                └─ финальные позиции → дедуп слипшихся
                                     └─ триангуляция Делоне (нормализованное пространство, вся выпуклая оболочка)
                                          └─ отсев треугольников, центр которых вне области
                                               └─ smooth_passes × [Лаплас-сглаживание → перетриангуляция → отсев]
                                                    └─ денормализация → Mesh + QualityMetrics
```

Реализовано из диплома: QuadTree с 2:1-балансировкой; поля φ, ψ, κ + коррекция κ у сингулярностей;
`h_t(φ,ψ,κ)`, кэшированный и билинейно интерполируемый по листьям QuadTree (`Tree.SampleHt`) —
брутфорс-поля вычисляются один раз на лист при постройке дерева, а не на каждую частицу каждую
итерацию; SPH с ренормализацией Шепарда γ_i, отталкиванием от границы, вязкостью (форма 26),
leap-frog интегрированием по CFL и двухфазной релаксацией; триангуляция Делоне; метрики качества;
экспорт.

**Не из диплома, добавлено отдельно:** после триангуляции — `smooth_passes` проходов Лаплас-
сглаживания (внутренние вершины → среднее по треугольным соседям, граница зафиксирована) с
перетриангуляцией между проходами. Эмпирически: качество SPH выходит на плато задолго до лимита
`iters` (на Zalesak `G_avg` = 0.844/0.840/0.844 при 500/1500/3000 итерациях — считать дольше не
помогает), так что расти дальше некуда без правки самой силовой модели. Сглаживание после факта —
дёшево и безопасно (не может сделать сетку хуже, только тянет к равностороннему) — и реально
поднимает `G_avg`: 0.84→0.90 на Zalesak и эллипсе, 0.85→0.88 на `kulman.dxf`, вплотную к референсу
диплома (0.91 на Zalesak).

Осознанные упрощения (эквивалентны на масштабе MVP, поведение метода не меняют):
- φ — точный signed distance, а не узкополосный расчёт + реинициализация Гамильтона-Якоби (нужна для скорости, не точности);
- κ — от ближайшей точки границы + затухание через ramp по φ, а не отдельный PDE диффузии вглубь;
- граничные частицы зафиксированы (при статичном поле h_t их эволюция вдоль контура — no-op);
- соседи ищутся каждую итерацию, без кэша Верле (только скорость);
- нет ghost-ячеек QuadTree (нужны при интерполяции полей между разрешениями).

**Не эквивалентное упрощение, известная регрессия:** коэффициент θ (`h_i ≈ θ·h_t(r_i)`,
раздел 3 диплома) реализован (`calibrateTheta` в `sphquad.go`), но **выключен по умолчанию**.
Калибровка по одной случайной реализации внутренних частиц слегка поднимает `G_avg`, но создаёт шов
в размере элемента на стыке границы и интерьера (граничные частицы сеются ДО того, как θ известен,
и остаются на нерасчёт-θ шаге) — на Zalesak `G_min` и доля плохих треугольников заметно росли.
Не стал шипать регрессию; нужно либо оценивать θ до расстановки частиц (дёшево, по интегралу
`1/h_t²` по площади), либо честно пересчитывать периодически внутри цикла релаксации, как в оригинале.

  `sharp_deg` в sph); (2) у выпуклого угла добавить отражение через саму точку угла — для прямых
  углов вершина попадает в угол точно; (3) обрезать ячейки по контуру (restricted Voronoi,
  пересечение многоугольников); (4) VoroCrust — пары сайтов вокруг контура, углы в выборке явно.
- `charge-voronoi`: `minCellArea` после перехода на ячейки только внутренних ничего не отсекает
  (0 срабатываний на тестах и пресетах) — кандидат на удаление.
- **Баг:** `export` пишет только `Mesh.Triangles` — для полигональной сетки (`charge-voronoi`)
  `-out` даст вершины без единой ячейки. Нужна поддержка `Cells` в .obj/.json/.msh.
- **Баг:** метрики на последней иногда итерации уходят в 0/фейк значения (заметно на лоуполи вроде)
