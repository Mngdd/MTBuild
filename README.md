# MTBuild

MVP генератора неструктурированных сеток 

Алгоритм краткой справкой — [`example_info.md`](example_info.md).

---

## Запуск

Нужен Go 1.24+. Зависимости подтянутся сами (`go.mod`).

```bash
# только загрузить геометрию и посмотреть контур
go run ./cmd/mtbuild-cli -geom internal/geometry/testdata/kulman.dxf -svg contour.svg

# построить сетку методом из диплома + экспортнуть
go run ./cmd/mtbuild-cli -geom zalesak -algo sph-quadtree \
    -param h_max=0.05 -param h_min_s=0.03 -param grade=0.3 -param iters=400 \
    -svg mesh.svg -out mesh.msh

# твой DXF
go run ./cmd/mtbuild-cli -geom internal/geometry/testdata/kulman.dxf -algo sph-quadtree \
    -param h_max=0.035 -param h_min_s=0.02 -param grade=0.15 -param iters=400 \
    -svg kulman.svg
```

Собрать бинарь:

```bash
go build -o mtbuild-cli ./cmd/mtbuild-cli
```

Тесты:

```bash
go test ./...
```

### Флаги CLI

| флаг | назначение | по умолчанию |
|---|---|---|
| `-geom` | путь к `.dxf` **или** имя пресета (`ellipse`, `zalesak`) | `ellipse` |
| `-algo` | алгоритм: `grid`, `sph-quadtree`. Пусто — только загрузить геометрию | — |
| `-param key=value` | параметр алгоритма, флаг повторяемый | дефолты алгоритма |
| `-svg` | куда записать SVG (контур, либо сетка если задан `-algo`) | не писать |
| `-out` | куда записать сетку: `.obj`, `.json` или `.msh` (Gmsh 2.2) | не писать |
| `-width` | ширина SVG в пикселях | `900` |
| `-spline-samples` | на сколько сегментов дробить сплайн при парсинге DXF | `200` |

Прогресс и снапшоты пишутся в stderr, метрики качества — в stdout.

### Параметры алгоритма `sph-quadtree`

Задаются в **долях габаритного прямоугольника** геометрии (не в мировых единицах),
поэтому одинаково работают для любой фигуры. Кривизна — в единицах `1/доля`.

| ключ | смысл | диапазон | дефолт |
|---|---|---|---|
| `h_max` | размер элемента вдали от границы | 0.01–0.5 | 0.09 |
| `h_max_s` | размер элемента на гладком участке границы | 0.005–0.4 | 0.06 |
| `h_min_s` | размер элемента на остром участке границы | 0.003–0.3 | 0.02 |
| `grade` | дистанция, на которой размер растёт от границы до `h_max` | 0.02–1.0 | 0.25 |
| `kappa_a` | кривизна, при которой размер достигает `h_min_s`; `0` отключает адаптацию по кривизне | 0–500 | 15 |
| `sharp_deg` | угол поворота контура, считающийся сингулярностью (острым углом) | 5–90 | 25 |
| `iters` | максимум итераций SPH | 10–3000 | 250 |

Алгоритм `grid` (тривиальный baseline): один параметр `h` — шаг решётки в мировых единицах.

## Структура

```
cmd/mtbuild-cli/          точка входа. Парсит флаги, грузит геометрию, зовёт алгоритм, пишет SVG+метрики.
                          Алгоритмы подключаются анонимным импортом (_ ".../sphquad") ради init()-регистрации.

internal/
  geometry/               канонические типы входа + загрузчики файлов
    geometry.go             Point, Polyline, Geometry{Outer, Holes}; ориентация (CCW/CW), bbox, Normalized()
    contains.go             point-in-polygon (even-odd), Geometry.Contains
    dxf.go                  парсер ASCII DXF: LWPOLYLINE, SPLINE (Де Бур), LINE (чейнинг в петли)
    preset.go               встроенные фигуры: ellipse, zalesak

  mesh/                    тип выходной сетки + метрики
    mesh.go                 Mesh{Vertices, Triangles}, Tri(i), Centroid(i)
    metrics.go              QualityMetrics + Evaluate: G, θ_min/avg, доля плохих <30°, гистограмма углов

  mesher/                  КОНТРАКТ «чёрной коробки»
    mesher.go               Mesher (Name/Params/Generate), ParamSpec, Params.Get, Frame, Sink, NopSink
    registry.go             Register / New / List — алгоритмы регистрируются в своих init()

    grid/                   baseline-алгоритм: регулярная решётка + граничные точки + Делоне + отсев по centroid
    sphquad/                МЕТОД ИЗ ДИПЛОМА
      sphquad.go              оркестрация всего пайплайна (см. ниже)
      init.go                 посев частиц: граничные (фиксированные) + внутренние (прорежённый lattice)
      field/
        field.go              φ — signed distance брутфорсом по сегментам
        analyze.go            ψ (расстояние до острых углов) + κ (дискретная кривизна границы) + коррекция κ у сингулярностей
      quadtree/quadtree.go    адаптивная фоновая сетка: дробление у границы, 2:1-балансировка, LeafAt
      sph/
        kernel.go             кубический сплайн-ядро W(r,h) и dW/dr (форма из диплома)
        cellgrid.go           uniform spatial hash для поиска соседей за O(N)
        contour.go            контур, параметризованный длиной дуги (для граничных частиц)
        sph.go                цикл релаксации: давление с ренормализацией Шепарда γ_i + отталкивание
                              от границы, вязкость (форма 26), leap-frog + CFL, двухфазная модель

  delaunay/delaunay.go    тонкая обёртка над github.com/fogleman/delaunay в наших типах
  export/export.go        экспорт сетки в .obj / .json / .msh (Gmsh 2.2)
  viz/svg.go              рендер геометрии и сетки в SVG (потребитель типов, алгоритмы его не импортируют)
```

Зависимости между пакетами направлены строго вниз: `cmd` → `mesher` + `viz`;
алгоритм → `geometry`, `mesh`, `delaunay`; `geometry` и `mesh` не зависят ни от чего.
Алгоритм никогда не знает про `cmd`, `viz` и другие алгоритмы.

## Что на входе и что на выходе

### Вход

1. **Геометрия** — замкнутый контур (внешняя граница + опционально дырки).
   Источник:
   - `.dxf` файл. Поддерживаются сущности `LWPOLYLINE`, `SPLINE` (разворачивается в
     ломаную алгоритмом Де Бура), `LINE` (отрезки сшиваются в петли по общим концам).
     Если замкнутых контуров несколько — самый большой по площади становится внешним,
     остальные дырками.
   - либо имя встроенного пресета.

   Файл превращается в `geometry.Geometry{Outer geometry.Polyline, Holes []geometry.Polyline}` —
   это всё, что видит алгоритм. Парсинг файла — забота приложения, не алгоритма.

2. **Параметры** — `map[string]float64`. Какие ключи бывают — алгоритм декларирует сам
   через `Params() []ParamSpec` (ключ, лейбл, min/max/дефолт/шаг). Не заданные ключи
   берутся из дефолтов, значения зажимаются в диапазон.

3. **`context.Context`** — для отмены расчёта.

4. **`Sink`** — куда алгоритм по ходу работы сливает прогресс (`Progress(stage, frac)`)
   и промежуточные снимки (`Snapshot(Frame)` — позиции частиц, стадия, номер итерации,
   а на финале и готовая сетка). В CLI это печать в stderr; в тестах — `NopSink{}`.

### Выход `Generate(...)`

- **`mesh.Mesh`** — `Vertices []geometry.Point` + `Triangles [][3]int` (индексы вершин).
  Плоская 2D-триангуляция, не 3D-модель.
- **`mesh.QualityMetrics`** — число треугольников, `GAvg`/`GMin`, `ThetaMinDeg`/`ThetaAvgDeg`,
  доля треугольников с углом <30°, гистограмма всех углов по 15°-корзинам.
- **`error`** — при вырожденной геометрии, отмене по контексту, сбое триангуляции.

CLI дополнительно рисует сетку в SVG (`-svg`).

### Пайплайн `sph-quadtree` внутри

```
Geometry
  └─ нормализация в единичный габарит (координаты → доли bbox, центр в 0)
       └─ поля: φ = signed distance; ψ = расстояние до острых углов;
          κ = дискретная кривизна ближайшей точки границы;
          κ_final = max(κ, (1 − ψ/ψ_max)·kappa_a)
            └─ h_t(x):  h_surf = h_max_s − (h_max_s − h_min_s)·clamp(κ_final/kappa_a)
                        h_t    = h_surf + (h_max − h_surf)·clamp(|φ|/grade)
                 └─ QuadTree: адаптивное дробление у границы + 2:1-балансировка (несёт φ и h_t на листьях)
                      └─ посев частиц:
                           • граничные — вдоль контура с шагом h_t
                           • внутренние — jittered-решётка, прорежена под плотность 1/h_t²
                           └─ SPH-релаксация (двухфазная: разгон с импульсом → полировка с обнулением скорости):
                                соседи (uniform hash) →
                                  γ_i (вес Шепарда, форма 35) →
                                  давление −(1/γ_i)·p0·(h_i⁴+h_j⁴)·∇W + отталкивание от границы (форма 36) →
                                  вязкость (форма 26) →
                                  leap-frog с шагом dt по CFL → сдвиг → сбежавших вернуть внутрь
                                └─ финальные позиции → дедуп слипшихся → денормализация
                                     └─ триангуляция Делоне (вся выпуклая оболочка)
                                          └─ отсев треугольников, центр которых вне области
                                               └─ Mesh + QualityMetrics
```

Реализовано из диплома: QuadTree с 2:1-балансировкой; поля φ, ψ, κ + коррекция κ у сингулярностей;
`h_t(φ,ψ,κ)`; SPH с ренормализацией Шепарда γ_i, отталкиванием от границы, вязкостью (форма 26),
leap-frog интегрированием по CFL и двухфазной релаксацией; триангуляция Делоне; метрики качества;
экспорт.

Осознанные упрощения (эквивалентны на масштабе MVP, поведение метода не меняют):
- φ — точный signed distance, а не узкополосный расчёт + реинициализация Гамильтона-Якоби (нужна для скорости, не точности);
- κ — от ближайшей точки границы + затухание через ramp по φ, а не отдельный PDE диффузии вглубь;
- граничные частицы зафиксированы (при статичном поле h_t их эволюция вдоль контура — no-op);
- соседи ищутся каждую итерацию, без кэша Верле (только скорость);
- нет ghost-ячеек QuadTree (нужны при интерполяции полей между разрешениями);
- интерполяция h_t — кусочно-постоянная по листу QuadTree, не билинейная.
